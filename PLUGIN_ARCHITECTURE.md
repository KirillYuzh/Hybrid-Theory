## 3. Внешняя критика и принятые решения

### 3.1. Что принято из критики (Compliance/R&D/C-Level)

1. **Заморозить плагины как первый шаг**. Стабильный монолит с чистыми внутримодулями — единственный путь для v1. Плагины — удел v2, когда появится реальный спрос и доказанная ценность ядра.
2. **Данные — король**. Без реальных размеченных данных ML-модель не имеет ценности. Приоритет №1 — партнёрства с биржами, разметка, внешние санкционные списки.
3. **Compliance — не опция**. Audit trail, объяснимость (SHAP→JSON→PDF), ролевой доступ — закладываются с первого дня, а не «пото».
4. **Операционная зрелость**. SLA, метрики, алерты, CI/CD, graceful shutdown — в архитектуре, а не добавкой.
5. **Лицензия не меняется**: AGPL-3.0 остаётся как есть. Dual-license — отдельное обсуждение с юристом, вне рамок этого документа.
6. **Compliance**: в этой ревизии фокусируемся на архитектурных решениях и их обосновании, не закая в юридические детали.

### 3.2. Что меняется в коде (по итогам критики)

- **Убираем 2 API** → один FastAPI с единым конвейером.
- **Убираем dummy fallback** → API стартует только с реально загруженными моделями.
- **Единый FeatureEngineer + единый скоринг** → один Pipeline, один Triage.
- **Audit trail** → добавляем `core/audit.py` (append-only JSONL в v1; Iceberg — в v2).
- **Ролевой доступ** → в v1 — API-ключ + базовая проверка; OAuth2/RBAC — в v2.
- **Нет CI/CD** → GitHub Actions + Makefile цели.
- **Нет lock-файла** → `requirements.lock` (pip freeze по чистому venv).

## 4. Что фактически переписано

### 4.1. Новая структура `src/kyt_engine/`

```
src/kyt_engine/
├── api/
│   └── app.py             # FastAPI: /health /predict /analyze /metrics /audit
├── core/
│   ├── contracts.py       # TxRecord, FeatureVector, ScoreResult, AuditRecord
│   ├── pipeline.py        # конвейер: features -> scorers -> triage -> sinks
│   ├── features.py        # единый FeatureEngineer (base + behavioral)
│   ├── scorers.py        # LGBM + KScore + External (Protocol Scorer)
│   ├── triage.py          # единственная политика оповещений
│   ├── sinks.py           # Prometheus, файл (для дашаборда), JSONL-audit
│   └── audit.py           # append-only журнал решений (v1: JSONL файл)
├── data/
│   ├── synthetic.py       # генератор для тестов (не для продакшна)
│   └── external.py        # внешние списки (OFAC/SDamDB) — интерфейс + заглушка
├── training/
│   ├── train.py           # обучение LGBM+ансамбль на Elliptic
│   └── drift.py           # PSI-дрейф + инкрементальное обучение
└── dashboard/
    ├── __init__.py
    └── app.py             # Dash-дашборд руководителя (порт 8050)
```

### 4.2. Контракты модулей (для subagents)

**Ядро (`core/`)** — не знает о `models/`, `training/`, `api/`. Только контракты и примитивы.

**`core/contracts.py`** — Pydantic-схемы/датаклассы:
- `TxRecord(tx_id, from_address, to_address, value, gas_price, gas_used, timestamp, block_number)`
- `FeatureVector(values: dict[str, float])`
- `ScoreResult(tx_id, risk_score, risk_zone, triage_level, lgbm_proba, k_score, vae_anomaly, external_risk, reasons)`
- `AuditRecord(...)` — для audit trail.

**`core/pipeline.py`** — класс `Pipeline` с методами:
- `__init__(self, features: FeatureEngineer, scorers: list[Scorer], triage: TriagePolicy, sinks: list[Sink])`
- `score_tx(self, tx: TxRecord) -> ScoreResult` — полный цикл.
- `score_batch(self, txs: list[TxRecord]) -> list[ScoreResult]`.

**`core/scorers.py`** — Protocol `Scorer`:
```python
class Scorer(Protocol):
    name: str
    def predict_proba(self, features: FeatureVector, tx: TxRecord) -> float: ...
```
Реализации: `LightGBMScorer`, `KScoreScorer`, `ExternalScorer`.

**`core/triage.py`** — `TriagePolicy` с порогами из `config.yaml` (0.3/0.7/0.2/0.9).

**`core/audit.py`** — `AuditLog` с методом `append(record: AuditRecord)` (JSONL в v1).

**`core/features.py`** — `FeatureEngineer` (fit/transform), обёртка над `features/base.py`+`behavioral.py`.

**API** — использует только `core/` и `schemas.py`. Без логики в эндпоинтах.

**`data/` и `training/`** — не импортируют `api/` (нет циклов).

Правила для subagents: каждый модуль импортирует только `core/contracts.py` + свои зависимости. Нет импортов `api/*` из `core/*`. Нет `Any` в публичных сигнатурах.

## 5. Целевая архитектура v1 (монолит с модулях)

```
kyt_engine/
├/api/                  # FastAPI (health, predict, analyze, audit)
├/core/                 # contracts, pipeline, scorers, triage, features, sinks, audit
├/data/                 # loaders, external labels, synthetic
├/training/             # train, drift
└/dashboard/            # Dash-дашборд руководителя
```

**Ключевое**: внутренние модули имеют явные границы, но без абстракций ради абстракций. Выделение в сервисы/плагины — только после стабилизации.

## 6. Механизм расширений v2 (безоверинжиниринга)

**Pluggy** (рекомендация) или простая папка `plugins/`.

```python
# kyt_engine/core/hooks.py
import pluggy

hookspec = pluggy.HookspecMarker("kyt")

@hookspec
def score_tx(features: FeatureVector) -> list[ScorerOutput]: ...

@hookspec
def triage(scored: list[ScorerOutput]) -> list[Alert]: ...
```

Правила:
1. Плагин не импортирует `kyt_engine.models.*` — только `core/contracts.py`.
2. Тяжёкие библиотеки — зависимость плагина, не ядра.
3. Ошибка в плагине не валит конвейер (try/except + счётчик errors).
4. Изоляция тяжёлых моделей — отдельные процессы/сервисы.

## 7. Почему так: объяснение ключевых решений

### 7.1. Монолит сначала

- **Сложность должна расти только когда есть спрос.** Пока нет пользователей и доказованной ценности, плагинная экосистема — это код, который никто не использует.
- **Тестируемость.** Монолит с чистыми модулями легко покрыть интеграционными тестами.
- **Скорость изменений.** Один процесс, один конвейер — проще отлаживать и деплоить.

### 7.2. Один API вместо двух

- **Дублирование скоринга** — источник расхождений (разные пороги, веса, схемы).
- Один конвейер → один внутренний контракт → однозначные ответы.

### 7.3. Без dummy-моделей

- Fallback на модель, обученную на случайных данных, — это **тихий вред**: API отвечает, но предсказания бессмысленны. Честный 503 с понятным сообщением лучше.

### 7.4. Audit trail изначально

- **FATF/GDPR** требуют возможности объяснить решение. JSONL в v1 — дешево, append-only, потом переносится в Iceberg/Postgres без изменения контракта.

### 7.5. API-ключ в v1, OAuth2 в v2

- Для пилота достаточно x-api-key + базовая проверка. OAuth2/RBAC — при появлении реальных пользователей и требований безопасности.

### 7.6. Лицензия не меняется

- AGPL-3.0 остаётся. Dual-license — отдельное решение с юристом, вне этого документа.

## 8. Операционная зрелость и SRE

| Категория | Метрики |
|-----------|---------|
| Нагрузка | QPS, latency p50/p95/p99, error rate |
| Модель | PSI дрейфа, ECE (калибровка) |
| Triage | Кол-во алертов по уровням |
| Инфраструктура | CPU/RAM, старт-тайм |

- Алертина: drift → warning, error rate > 1% → critical.
- Graceful shutdown (uvicorn `--graceful-timeout`).
- Liveness/Readiness — уже в k8s-манифестах.
- CI/CD (GitHub Actions: lint, test, build) — в Makefile.
